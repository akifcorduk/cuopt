What changed against the synthesis, and why.
1. Where the rules live. The synthesis had a family exchange_t that scanned every row at its first call and every row with an activity event afterwards, kept four prices per scanned row, and a second family for the conversion that also started from all rows. Both critics showed what that costs (89 of the 240 benchmark instances have integer columns only and can never fire; a price that went stale ended a test for good). Version 2 takes the worth critic's smallest design with three changes: implied equations are a column test inside the dual column family of the nine rules; stuffing is a step of the row visit of the singleton-column family; the single-equation rule and the dominated column share a small family exchange_t that is driven by columns with at most one lock in a direction and is skipped in O(1) when the state has no live continuous column; the conversion (equation test, weak test and scaling together) is driven by a per-row count of live continuous columns that the state keeps.
2. Validity. All eight defects of the validity critic are accepted and repaired: the implied test allows only the rounding of its own candidate; no rule of exchange_t changes a lock or a side and the rule that does (implied equations) runs in another family call; the integrality predicate has the drift guard of row tightening; the type of a column at a record is a notion of the stack; a conversion sets rounded bounds as the start step does and is refused where that would widen a bound; the crush of a conversion reads saved rows; a column scaling scales the offset as well; every fixed case names the counter that must move.
3. Three holes of the same kinds in the nine-rule design and in Stage 1, found while checking the fixes: R6 keeps bound and row with the same tolerance band (my model in models.py loses -0.25 to -0.2); the integrality predicate of R2 and R5 for an integer column has no drift guard; the alias forest's edge test (G/src/alias_forest.cpp:44-57) has none either. The first two are in the list of changes to the nine-rule design; the third is existing code and is named under risks.
4. Worth. The table of dependent instances is rebuilt from the ladder runs. neos-827175 and irish-electricity need none of the five rules; mushroom-best is not an implied-equation instance; implied equations are worth 8 rows on physiciansched3-3 without the conversion, not 209; on the 40 testbed instances the five rules are worth one instance, supportcase42 (140 rows), and ns1208400 where the engine already has HiGHS's size. A further reading that the critics did not have: the 173 rows that the conversion costs on physiciansched3-3 when HiGHS's implied-equation switch is off are explained by that switch also disabling HiGHS's integrality proof for substituting a converted column (G/baseline/HIGHS_DIAG.md:457-460, H/HPresolveImpliedInts.cpp:28-34); in the engine that proof is R2's and R5's own test. That is an inference from the source, not a run.
5. Order. Implied equations; implied integers with the scaling; stuffing; single equation; dominated column; then the gate. Each piece of state and test machinery arrives with the rule that reads it.

5. Shared internal code. src/implied.hpp (from M0) gets implied_by_row(st, row, slot, side): true for an infinite bound; else the side must be finite under the side guard and the activity may hold no infinite term but the column's own; if the activity is not fresh it is summed from scratch (recompute_row_activity, charged to the budget); the candidate c and its slack s are those of bound propagation; true when c + s >= bound (lower) or c - s <= bound (upper). Why this accepts a bound that make_explicit wrote from the same row: that bound is an earlier candidate moved outward by its slack, so it lies on the safe side of the true quotient, the true quotient only moves to the safe side as other bounds tighten, and the new candidate is within s of it. src/integral.hpp: integral_denominator and integral_for(st, row, slot, side) with the drift guard (answers, validity 3), shared with row tightening and with the integer case of R2 and R5. src/saved_row.hpp and the saved-row pool of the nine rules: tight_row and implied_integer store rows there; comp_fix terms and row_exchange entries have their own pools and count against the same saved_row_factor.

6. Records (include/gprs/postsolve.hpp, src/postsolve.cpp), after the kinds of D2 item 5: tight_row {row, col, saved} (L1); implied_integer {col, mode, first, count} (L2); col_scale {col, scale} (L2, second step); row_exchange {row, mode, first, count} with entries {col, coefficient, bound_from, bound_to, role} (L3, reused by L4); comp_fix {col, value, first, count} with terms {col, factor} (L5). postsolve_t gets conversion[col], integer_at(col, position), integer_now(col) (L2); the push assertions of fixed_col and alias (src/postsolve.cpp:101, 113) and the rounding in postsolve() (:146) read integer_now. The forward replay of crush (built in M3) gets one step per kind: tight_row and implied_integer evaluate saved rows, row_exchange moves entries, comp_fix moves weight, col_scale divides; crush is then O(columns + records + saved entries of these records). postsolve() undoes col_scale and comp_fix and ignores the other three. stack_consistent and postsolve_hash name every new kind and field; an unknown kind is an error.

7. What each family does in a call.
- dual_cols_t (D2 item 7) with rule A: in its column pass, for every candidate column, R7 first, then rule A if the column is still live. R8 follows as in D2; it must collect its rows after the column pass and read 'no equation' and the lock counts at application, because rule A changes sides and locks inside the call.
- singleton_cols_t with rule S: a row visit applies R2 when the row is an equation, R5 when it is not, then rule S when the row has exactly one finite side and at least two candidates, and otherwise R3; rule S reads the singleton columns that the visit found.
- implied_integer_t: active when its switches allow and live_cont_cols > 0. One pass: take the row list; a listed live row with row_cont_size != 1 costs one visit; a row with exactly one continuous column gives a candidate (cache, item 3 of rule B); candidates in index order, each once per pass: equation test, then scaling, then weak test. The family repeats passes while its list is not empty and the budget allows.
- exchange_t: active when not primal-only (by its rule index, as dual fixing, src/presolve.cpp:153-156) and live_cont_cols > 0. Work data that outlives a call: one byte has_source per row and the count of marked rows. One pass: (a) take exchange_sources; for a listed live column and each direction d with at most one lock: with exactly one lock the walk of the column finds the lock row; a continuous column marks and schedules it, an integer column schedules it only if it is marked (the walk is made only while a marked row exists); with no lock, for a continuous column whose bound in d is infinite (from L5), every row of the column is marked and scheduled. (b) take the row list; a listed live row is scheduled if it is marked, else it costs one visit. (c) scheduled rows in index order, each once: one scan gives the compensators and their prices (L5), the marks and sums of rule E; the mark of the row is cleared when no continuous column of it passes C1 in any direction; rule E is applied if the row is an equation; the free columns of a row with a price become candidates (L5). (d) from L5: take the column list exchange; the candidates are these and those of (c), in index order, each once; rule D. A fixing clears the cached scans of the rows of the fixed column. The family repeats passes while its lists are not empty and the budget allows; the stop is tested between two rows and between two columns; unvisited rows and columns go back on the lists.

8. Round and modes. Cascade, parallel rows, doubleton equations, simple probing, singleton columns (with S), dual columns (with A), parallel columns, exchange, implied integers, each followed by end_phase(). The conversion is last so that in every round the parallel columns, R3 and the dual rules see a column while it is still continuous. Primal-only mode: rule A, rule S and the weak test are off by their own test of opt.primal_only; exchange_t is not active; the equation test and the scaling are on. Both new families join fixed_terms_matter() (src/presolve.cpp:293-297), the renewed test after absorb_fixed_terms (:354) and the fixed-point expression (:357-358). phase_hash gets two more entries per round. The places that write the families out (D2 item 12) follow rule::count.

9. Fixed-point flag. It additionally requires that neither new family is waiting, stopped or limited. Every decision is a function of the state (smallest price, sort keys, ties by index, named constants). Every premise has an event; read at the push sites of src/state_ops.cpp:
- Rule A is tested for column j by dual_cols_t. Cost, locks, entries and type of j list j (set_cost :325, lock sites, set_col_integer). The bound of j, the sides, entries and activities of its lock row r, and through them the bounds of the other columns (which the implied test and the drift of an integer source read), list r on the family's row list, whose columns are candidates.
- Rule S is tested in the visit of a row. Costs and singleton status of the candidates list the column, which leads to a visit of its row; bounds, sides and entries list the row.
- Rules B and C are tested for the only continuous column of a row. A row reaches one continuous column only by fix_col, delete_entry, move_entry or set_col_integer, all of which push row_event::entries; coefficients and sides list the row; a bound of another column (drift) or of j itself (weak test) lists the row by an activity event; the cache is keyed so that a change of the row's entries, fixed terms or sides forces a scan, and a row whose answer depends on bounds is scanned at every listing.
- Rule E is tested in the scan of a marked equation. The mark is never missing where it is needed: a continuous column starts to point at a row only when one of its lock counts changes to 0 or 1, when it gets a new entry, or when its cost or type event fires, and each of these pushes few_locks, after which step (a) marks the row; a mark is cleared only by a scan that finds no such column. A column of the row gets mark +1 or -1 only through its lock count (few_locks; an integer column's walk schedules the marked row) or its cost (set_cost). The sums change with bounds, the side and fixed terms, which list the row.
- Rule D is tested for column k. Its cost and locks list k on the list exchange (a deleted locking row without a price is the case that needs this list). Its target bound lists all its rows by an activity event; for k to be fixable every locking row is marked, so one of them is scanned and makes k a candidate. A price changes through the compensator's cost or lock counts (few_locks, which schedules the compensator's rows; a count that leaves 0 or 1 only removes a compensator), through a new entry (few_locks from move_entry), through C2 (an activity or side event of the row, or a bound that became infinite) or through a fixing inside the pass (cached scans of that column's rows are cleared).
Caps: comp_ratio_limit, price_limit, col_scale_limit, the size guards and ii_refused_bound are functions of the state; the saved-row limit reports limited. A call that stops on its budget returns its lists. Not covered, as today: the last bits of a stored activity. The second-presolve tests (tests/test_engine_fixed_point.cpp, the sample in the campaign) test this item.

10. Determinism. No hash container; rows and columns are processed in index order; ties go to the smaller column index (the source of rule A is the first column in index order that passes, the two best prices of a row, the stuffing key); the absorbers of a row_exchange record are in index order; the new arrays and lists enter state_hash.

11. Work and memory. Rule A: O(1) per visited column, a walk only for a column with a cost and one lock in its cost direction. Rule S: nothing below two candidates. implied_integer_t: one visit per listed row; on the 240 benchmark instances the first call is one visit for each of the 10.8 million rows of the 151 instances with continuous columns and nothing on the other 89 (predicted from the instance sizes; seconds unknown until measured). exchange_t: nothing on those 89; elsewhere one walk per listed few-lock column and one scan per marked row that is listed. Reported per instance and family at every milestone: rows scanned, rows scanned without a finding, columns walked, findings, work in passes, seconds. Ceilings are reports until measured (AM E.6). Memory: 4 bytes per row in the state; 13 bytes per row for the implied-integer cache; 5 bytes per row and 4 per column for exchange_t plus 64 bytes per row scanned in a pass; all inside the reported peak.

CHECKS
Written against the checks as D2 leaves them (Checks A to L: compose_records with check variables, anchors and next_anchor; the objective test; the postsolve test by forward replay; crush clauses 1 to 5 with the replay; the oracle's crush condition 'feasible and not above, equal when dual_findings == 0'; wrong engines named with the check that must catch them) and AM D. Principle as there: every rule has a forward map that the crush replay performs, so for any feasible point x of the original model the crushed point is feasible in the reduced model with an objective not above, in default mode too. All five rules restrict (or, for the equation test and the scaling, keep every feasible point), so the oracle and the crush of feasible points decide optimality, and the structure check guards the stack, the types and the column map. Every record kind arrives in the milestone of its rule with its reader in the structure check, its crush step with unit tests of crush alone, and wrong engines in G/check/make_mutants.py; a wrong engine that the named check does not catch stops the milestone. All generator knobs default to 0.

A. Structure check (G/check/structure_check.hpp).
- Types. The check keeps, in its own forward pass over the stack, the position of each column's implied_integer record and reads 'integer at a position' from it wherever it reads model.col_type today (the integrality of a fixed value and of an alias, the split of a merge, the rounding of its second implementation of the undo of col_from_rows, the test points). Types clause: a column that is integer in the original is integer in the reduced model; a reduced column is integer only if its original column is integer or has an implied_integer record.
- tight_row: contract only (the row was not taken out by an earlier record, the column not removed, the saved entries name columns that are live at the push and not the column, finite coefficient other than zero, finite side); no change of a map; an error in a primal-only result. Its saved row is no anchor: next_anchor enumerates col_from_rows records only. The header paragraph at lines 81-102 gets the sentence that a side tightened for a cost reason passes kept_rows and that the check cannot see whether it keeps an optimum.
- implied_integer: the column is continuous in the original, live at the position and named by no earlier implied_integer record; a weak mode is an error in a primal-only result; every saved row names only columns that are integer at the position (which catches a row with a second continuous column) and is integral for the column by the check's own computation of ratios and side (counter integral_failures); for mode equation the saved row is proved from the next anchor of its row when the two are proportional (counters conversion_tested, conversion_untested). The drift guard is not recomputed (it needs bounds at the position); fixed test T3 covers it.
- col_scale: finite positive scale; the column is continuous at the position; the reverse pass multiplies scale and offset of the column's map; the objective test of D2 Checks D(2) reads the scaled cost through the same map; the postsolve test compares postsolve() with the composed records.
- row_exchange: names a live row and columns that no earlier record removed, finite coefficients other than zero, finite bounds, valid roles; absorbers and continuous candidates are continuous at the position; integer candidates of one stuffing record have equal |coefficient|; the fixed_col records that follow are exactly its fixed entries with bound_to as value; absent from a primal-only result.
- comp_fix: read as a fixed column (value finite, integral for a column that is integer at the position, inside the original bounds through the maps); its terms name other columns that no earlier record removed and that are continuous at the position, with finite factors other than zero; absent from a primal-only result.
- What it cannot prove: that a tight_row had its bound implied and its lock single, that a weak conversion or a fixing of rules S, E, D keeps an optimal point. Those are restrictions.

B. Crush check (G/check/crush_check.hpp) and real instances. The argument at lines 20-39, rewritten by the nine rules as an induction over the records, gets one step per kind: tight_row (the moved point is the exchange of rule A), implied_integer (equation: the point is moved onto the equation it satisfies within its tolerance; weak: the rounding of one column), col_scale (a change of units), row_exchange and comp_fix (the recorded exchanges). Clauses 2 to 4 are verdicts in default mode. Clause 5 (primal-only, z equals x): a column converted by the equation test is compared with x up to check_tolerance * max(1, |x|) plus the residual of x in its saved equation divided by |a|; a scaled column needs no exemption. After every milestone: assertion build, structure check and crush check on all 240 benchmark instances and the testbed in default mode, primal-only mode and with the dual sub-rules off.

C. Oracle and generator (G/tests/oracle.hpp, oracle.cpp). The oracle's data are integers up to 3 and powers of two (oracle.hpp:76-106), so it decides lock counts, cost signs, sides, types and roles exactly and sees no tolerance.
- L1: knob p_tight_source: a row without a line column that has one finite side or a range gets a continuous line column with at least two entries whose cost pushes it against that row, with its other entries in rows that do not lock it in that direction, and its bound in that direction infinite, exactly the row's candidate, or one unit too tight (must not fire); variants with a second locking row, zero cost, and an integer line column with coefficient 1 (fires with integer_sources) or coefficient 2 and an odd side (must not fire).
- L2: knob p_unit_line: a continuous line column gets coefficients that are integral multiples of its own in all its rows, integral sides and integral bounds; variants with one fractional ratio, a side moved by 1/2, a bound moved by 1/2, an equation among its rows, and a coefficient 2, 1/2 or 1/3 on the line column in an equation (scaling). The reduced model has an integer line column, which the class allows.
- L3: group rows, the one extension of the class in this design: a row may hold several line columns when each is continuous, has two finite bounds and has no entry in another row; at most three per row. For every assignment of the enumerated columns solve() treats the row as a one-row linear program over the group and enumerates its vertices (every member at a bound, or all but one at a bound and the row tight at a finite side); with finite bounds there is no ray. Tested against a grid search (tests/test_oracle_brute.cpp) and against the old solver on old seeds before a rule uses it; two continuous singleton columns of one row are both a twin pair of the nine rules and a group, and the two solvers must agree. Knob p_stuffing_group: a one-sided row gets two or three singleton columns, all continuous with finite bounds or all integer with equal coefficient, costs that push against the row, a side on the boundaries of the two tests and inside the range; must-not-fire variants with unequal integer coefficients and with a range.
- L4: knob p_single_equation: an equation over enumerated columns gets one to three singleton columns (enumerated, or continuous with finite bounds as a group) with the cost signs of the pattern, and its side on, one below and one above the end of the range that decides the test.
- L5: knobs p_penalty_col (a continuous line column with one infinite bound and a cost against its free direction, in one to three rows that do not lock it in that direction, or in exactly one equation or ranged row with its bound there implied), p_dominated_col (an enumerated column in those rows whose cost is drawn at the threshold, one below and one above) and p_cover_source (rows x + s >= 1 whose continuous s has a second row that does not lock it). Outside the class: rule D with a continuous fixed column and a compensator that has further rows, rule E with absorbers that have further rows; these rest on the planted-point test (tests/test_e2e_planted.cpp, extended with such rows) and on the real instances.

CHANGES TO THE NINE-RULE DESIGN
- M0: nothing to build. To confirm when M0 lands, all already asked by AM A.2: the list masks are uint16_t (this design ends at 13 row lists and 7 column lists), the option draw of gprs_fuzz and the other places of D2 item 12 follow rule::count (12 at the end), an unknown record kind is an error (five more kinds come).
- M1 (R2 and R5, integer column): the integrality predicate gets the drift guard of row tightening (G/src/rules_tightening.cpp:126-145) and lives in one internal function integral_for in src/integral.hpp. D2's test 'ratios integral within tol.zero, |a round(a_i/a) - a_i| <= tol.zero' has no range term. Model (inferred from the text of D2 R2, not run): x - 1.0000000005 y = 0 with x an integer singleton column and y integer in [0, 2000000]: R2 passes, the undo restores x = y, and the original row is violated by 5e-10 y, that is 1e-3 at the upper bound. Rules A, B and C of this design call the same function.
- M1 and M5: every undo, crush step, push assertion and check clause that depends on a column type reads it through postsolve_t::integer_at(col, position) (or integer_now for a push): the rounding in the undo of col_from_rows ('rounded to the nearest integer for an integer column', 'its finite end rounded inward for an integer column', D2 R2 and R4), and the types of a merge ('types from postsolve_t::col_type', D2 R9) with its second implementation in the structure check. Until L2 the function returns col_type[col], so no result changes; if M1 is already written, L2 edits those lines instead.
- M1 (structure check): next_anchor finds saved rows through the col_from_rows records, not by walking the saved-row pool, so that the rows which tight_row and implied_integer records put into the same pool from L1 on are never offered as anchors.
- M3 (R6): the absorb test ('can absorb in a direction') uses the shared implied test in its rounding-only form, not implied_tolerance. R6 keeps the absorber's bound and its row, so the band of 2e-7 acts as in validity defect 1. Model (mine, S/models.py, section R6): 10 p + 10 q - w = 0, p in [0, 0.5 - 1.5e-7] and q in [0, 1] continuous with cost -1 each, w integer in [0, 5] with cost 0.05: R6 fixes q at 0 with p as absorber (candidate 0.5 within the tolerance of the bound), propagation then gives w <= floor(4.9999985 + 1e-6) = 4, and the optimum goes from -0.25 to -0.2. R2 and R5 may keep implied_tolerance: their column leaves the model.
- M4 (R8), binding from L1 on: R8 collects its rows after the column pass of dual_cols_t and reads 'the row is no equation' and the lock counts at application. D2's text already evaluates every test before the first substitution; it becomes a requirement because rule A, a sub-rule of the same family, changes sides and locks inside the call.
- M1 to M5, one rule to keep in mind, with no code now: no family keeps a fact that depends on a column type across calls unless it follows the events of set_col_integer (row_event::entries for the column's rows, the column events for the column). This includes the per-row counts of AM D.3 if they count continuous singleton columns. L2 reruns the tests and campaigns of the nine rules with conversions happening and carries the wrong engine ev_type.
- Not required, named so that it is not found late: R3 could take an integer singleton column whose row is integral for it (the projection then has no hole on the lattice of the rest). It is the remedy if L2 measures columns that R3 lost to the conversion (statistic blocked_r3); the phase order (singleton columns before the conversion in every round) is the first defence.

RISKS
- Nothing was run in the engine. Rules A, D and E were tested in exact arithmetic on tiny models (S/exact.py); that test has no tolerances, no crush maps, no stored activities and no interplay with the nine rules. Stuffing, the weak test and the scaling rest on reading (the validity critic confirmed the first two). The oracle campaign of each milestone is the first test of the engine's form.
- Reach is inferred from counters and sizes; the model files are not on this machine and the node is down. That the chain conversion, R7, redundant rows, R5 carries supportcase42, that the general form of rule D covers b1c1s1's two 4-entry columns, and that R2's and R5's own integrality proof avoids the 173 rows the conversion costs HiGHS on physiciansched3-3 are inferences. L0's trace and L2's and L5's reports confirm or refute them; none is credited in a gate before that.
- The repaired tolerance (rounding only on the unsafe side of the implied test) is stricter than HiGHS and than the first design. A column whose bound differs from its row's candidate by more than the candidate's rounding, but by less than HiGHS's 1e-7, is no source and no locked compensator here. Instances with non-integer data can lose firings; ie_blocked_bound counts them. The same holds for the rounding-only sums of rules S and E against HiGHS's 1e-6.
- Three holes of the same kinds exist outside the five rules and were found by reading, not by a run: R6 of the nine rules (my model loses -0.25 for -0.2), the integer case of R2 and R5 (no drift guard), and the alias forest of Stage 1 (G/src/alias_forest.cpp:53-57 bounds the rounded coefficient by tol.zero without the range of the parent; a doubleton equation x - 1.0000000005 y = 0 between integers with y up to 2e6 would be its model). The first two are in the changes list; the third is existing code of the engine and needs its own look. The oracle cannot show any of them (integer data).
- The marks of exchange_t (has_source) must never be missing where a rule could fire. The argument rests on the push sites of G/src/state_ops.cpp that I read (item 9 of the state section). A site that is missed, or added later without the event, loses reductions and makes the fixed-point flag wrong; it cannot produce a wrong reduction, because every scan reads the state. The second-presolve tests, the sample in the campaign and the wrong engine ev_few are the safeguard.
- The type change is the first write of col_type after construction. The alias forest's root choice, the type rules of the parallel columns, R3, the marks of bound propagation and any per-row count of the nine rules that depends on a type were written under 'no type change'. The events of set_col_integer, integer_at in the stack, the rerun of the nine rules' tests in L2 and ev_type address it; a family that caches a type without an event would act on a stale one.
- A conversion can make an instance larger: a converted column is no column of R3, no compensator, no absorber, and a source of rule A only with the proof. HiGHS itself ends 3% larger on blp-ic98 and blp-ar98. The phase order (conversion last in every round) is the defence; L2 stops on any instance that grows, and the remedies are the R3 extension of the changes list or a default of the switches.
- Rule A lives in the family of R7 and R8, which the nine-rule work is building now. A change of that family's column pass or of R8's row collection after L1 can break the order the rule relies on (R8 reads the state at application). The requirement is in the changes list; the test is fixed case F5 and the campaign with all three sub-rules on.
- Crush now holds real logic: saved-row evaluations (tight_row, implied_integer), two exchanges with roles (row_exchange), linear compensation (comp_fix), a scaling. Three checks lean on it, and a crush error looks like a rule error on a point that is not optimal. Unit tests of crush alone and one wrong engine per record that skips or bends the replay are the safeguard. The weak-mode crush uses a tolerance of its binding row; a traced false alarm of the crush check on a real instance is still possible where terms cancel.
- The oracle gets new solver code (vertex enumeration for group rows) next to the twin split of the nine rules. An error there passes wrong engines or fails right ones; it is tested against a grid search and the old solver before a rule uses it. Rule D with a continuous fixed column and rule E with absorbers that have further rows stay outside the class.
- Time and work of the two new families were not measured. The predictions (nothing on 89 of the 240 benchmark instances; one visit per row at the first call of implied_integer_t; scans only on marked rows) are derived from the design and the instance sizes. An instance where most rows hold a slack with a cost has a mark on most rows, and exchange_t then rescans every row with an activity event, about one propagation sweep per round; the per-call budget bounds it at the price of a cleared flag.
- Rounds. An implied equation reaches the doubleton equations and R2 only in the next round, a conversion reaches R7 only in the next round, and max_rounds = 20 counts the whole presolve. Chains through the new rules can end on that limit and clear the flag; L1 and L2 report the rounds.
- col_scale changes the meaning of a column index for every later record and by-product, as the merge does. Any by-product exported in reduced indices must be in scaled units, and the adapter needs the marker.
- Solver quality is not tested locally. Turning inequalities into equations and continuous columns into integers changes what the solver sees; the milestones measure sizes only.
- Sources. PaPILO was not read. I did not read the structure check beyond its header and rely on D2's description of how it works; a difference between that description and the file changes the check part of L1 and L2, not the rules.

DECISIONS FOR THE OWNER
- 1. No stored bounds on row duals. The plan (P/DESIGN.md:130-131) and AM A.2 expect the five rules to bring bounds on the row duals as new state. Read in HiGHS by three designers, two critics and me: every such bound is cost over coefficient of one column with at most one lock in a direction, so it is a function of the state. Recommended: accept the design without that state and reword the two sentences. Cost if accepted: none measured; rule D recomputes prices per pass. Cost of the alternative (HiGHS's kept bounds): about 24 bytes per row and 44 per column in the state, a reset in about a dozen state operations, the same on the device engine, and stale bounds as a new kind of error.
- 2. 'Implied up to rounding' in place of the plan's 'strictly implied' (P/DESIGN.md:488-489). The exchange proofs need only that the bound holds wherever the lock row holds; the tolerance of the first design was broken by the validity critic and is now the rounding of the candidate. Recommended: implied up to rounding. Cost: a stricter test than HiGHS's for singleton columns (HiGHS allows 1e-7 there); ie_blocked_bound counts what it loses. Cost of the strict margin for columns with more than one entry, as HiGHS and the plan have it: every column whose bound was made explicit from its own row stops being a source after make_explicit and in a second presolve.
- 3. Several implied premises in one dominated-column fixing. The plan's guard says at most one per derivation (P/DESIGN.md:489). Rule D uses one per locking row that has a locked compensator, with the proof that they cannot lean on each other (each is used in its own row, where nothing else moves) and 34,110 exact test applications without a lost optimum. Recommended: the per-row form. L5 reports how many fixings on the 240 and the testbed use two or more; one named constant restores the limit of one if you want the letter of the guard, at the price of those fixings.
- 4. An integer column as the source of an implied equation. The plan's guard says dual arguments use continuous columns only (P/DESIGN.md:488); the nine-rule design already lets R5 move an integer singleton column when its row proves integrality. Rule A does the same for any integer column whose lock row is integral for it (switch integer_sources, designed on). It goes beyond HiGHS for true integers and replaces HiGHS's use of converted columns as sources. Recommended: on. Cost if on: one more proof to test (wrong engine ie_int, oracle knob). Cost if off: a column that the conversion made integer stops being a source; how many reductions that loses is unknown until L2 reports both settings on physiciansched3-3 and savsched1.
- 5. The type of a converted column. Designed: integer in the state and in the reduced model, with result_t::implied_integer as a flag 'continuous in the input'; no third column type, although AM A.2 leaves room for one and the plan names the order integer, implied integer, continuous (P/DESIGN.md:493). A third type would be needed only if the adapter is to hand flagged columns to the solver as continuous, which is safe only while the row that proves integrality is still in the reduced model and no later reduction used the integrality. Recommended: no third type. Say if cuOpt should get such columns as continuous; that is then a rule of its own, not a flag.
- 6. The column scaling (HiGHS's transform x = s z). It is part of HiGHS's conversion switch, so 'all cheap rules' includes it. Designed: second step of L2, only where the equation test fails without it, within a factor of 1024. Measured worth: no size change on the testbed, at most physiciansched3-3's 28 rows on the 240, shared with the conversion. Cost: a state operation that rewrites a column, a record that changes what a column index means, the marker for the adapter. Recommended: build it as the second step, because you asked for every cheap rule and because 1,400 columns on neos-4647030-tutaki become integers through it; dropping it costs nothing that the stored runs can show.
- 7. Whether the conversion is on by default. The equation test and the scaling are primal; the weak test is a dual reduction and is off in primal-only mode by the plan. HiGHS's own run ends 3% larger on blp-ic98 and blp-ar98 with the conversion on, and a converted column loses roles here (R3, compensator, absorber). Recommended: on, last in the round, with the three switches kept; L2 stops on any instance that grows and comes back to you with the numbers.
