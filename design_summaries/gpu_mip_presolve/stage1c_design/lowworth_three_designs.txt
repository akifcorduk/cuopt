Result. The five rules become seven sub-rules in two new families that run after the nine: dual_columns_t (implied equation, compensated fixing of a dominated or weakly dominated column, the single-equation extension, column stuffing) and implied_integer_t (equation test, weak test, and last HiGHS's column scaling). No bound on a row dual is stored. The reason is a reading of the HiGHS code: every implied row-dual bound HiGHS keeps is c_j / a_rj of one source column j (H/HPresolve.cpp:684-725), because the original dual bounds are only 0 or infinite (H/HPresolve.cpp:147-148, 975-1011). That number is the price of moving the activity of row r by one unit with column j, it can be recomputed in O(1) from costs, lock counts, one bound and the stored activities, and so a cache that lives for one call of the family replaces HiGHS's stored bounds, sources and five reset events.

Every rule is stated as an exchange with a forward map, so that the crush of any feasible point can be tested in default mode: the implied equation moves only its source column; a dominated column is fixed together with one compensating column per locking row; the single-equation rule and stuffing refill one row greedily; the weak implied-integer test rounds one column down or up. Six record kinds are added (tight_row, comp_fix, equation_shift, stuffing, implied_integer, col_scale). Two checks are designed before any rule: an extension of the oracle class to rows whose continuous columns are all singleton columns with finite bounds (solved exactly by enumerating the vertices of a one-row linear program), which makes stuffing and the single-equation rule exact in the oracle, and the type clause of the structure check for columns that become integer.

Design in short. The state gets no bounds on row duals. I read HiGHS's implied row-dual bounds (HP:657-733) and found that each of them is produced by one continuous column that nothing but the row holds in one direction; with the lock counts and the O(1) row candidate our state already has, that premise can be tested in O(1) per row entry. So a row's dual bounds are a derived value: one scan of the row gives them, a table in the family's work data keeps them for the length of one call, and every use is tested again on the state at application. On top of that all five rules are stated as exchange arguments that move named columns, so each has a forward map (crush) that the crush check and the planted-point test can run on any feasible point: (1) dominated column = the lock rule with every objecting row paid for by a compensator column; (2) implied equation = a continuous column pushed by its cost against its only lock row; (3) stuffing and (5) the single-equation extension = fixings in one row compensated by other columns of that row, reading lock counts and cost signs only; (4) implied integers = a type change continuous to integer with a rounding step in crush, plus HiGHS's column scaling. Two new families (row_duals, implied_integer), five record kinds, two state operations (make_integer, scale_col), seven milestones.

I tested the rule conditions as designed in exact arithmetic on tiny random MIPs (scripts in S, not project code): about 9,300 single applications and 3,075 chains of reductions, including 2,025 dominated fixings that rest on two or more implied premises and 2,636 stuffing applications with the wider second condition, without a lost optimum; fourteen deliberate errors were caught. Tolerances, floating point, the crush maps and the scaling transform are not covered by that test.

Design. HiGHS's original row-dual bounds are 0 or infinite by row sense (H/HPresolve.cpp:147-148), so its 'Orig' dual sums are zero and their infinity counts are our lock counts; an implied row-dual bound is cost over coefficient of a non-integer column with at most one lock in a direction whose bound there is infinite or implied (H/HPresolve.cpp:657-725). Therefore no dual state is stored: one new family, exchange_t, rebuilds a table of row prices per call and proves every reduction by an exchange that the crush replay performs. Five rules R10 to R14 in the order of instance dependence: R10 implied equation (a continuous column with a cost and one lock in its cost direction makes the lock row tight), R11 dominated column by the reduced-cost bound with recorded compensators, R12 implied integers (HiGHS's weak test as the gate for dual bound strengthening on continuous columns, plus result flags by the equation test; no type change), R13 single-equation group, R14 stuffing. Two record kinds (tight_row, exchange_fix). Six milestones L0 to L5.
